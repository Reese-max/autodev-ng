# M10.5 多專案常駐改造 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 常駐層（排程/bot/web）為所有專案服務：丟 config 進 configs/ 即納管、刪 config 即退場、跨專案全域日頂、bot/web 一進程多專案。

**Architecture:** 方案 B——Windows 排程當 supervisor（boot＋15 分 refire＋各 daemon 自己的 lock 去重＝現成復活機制）。daemon 核心只加「config 消失自退」；錢防線加 kernel 小檔 `src/globalcost.ts`；bot/web 由單 cfg 閉包改為 `Map<專案名, 執行環境>`，`--config` 單專案模式全程保留（向後相容）。spec：`docs/specs/2026-07-14-m10.5-multi-project-design.md`。

**Tech Stack:** TypeScript ESM、better-sqlite3、discord.js v14、vitest（serial）、Windows schtasks/cmd。

## Global Constraints

- kernel 帳 `wc -l src/*.ts | tail -1` ≤2700（現 2571；本計畫 kernel 面估 +60 → ~2631）。每 task 結束實測記錄。
- `npm run build`＋`npx vitest run`（**基線 652 tests**）全綠；驗 exit code 一律直跑＋`echo EXIT=$?`，禁止管線吞碼；既有測試斷言不動；測試禁 sleep；禁改 vitest.config.ts。
- `--config` 單專案模式（bot/web/daemon）行為與 M10.0 byte-identical——多專案全部走新旗標 `--configs-dir`，未用新旗標＝零行為變化（硬回歸線）。
- fail-open 總則（spec §4）：壞 config 跳過不拖垮鄰居；全域帳查詢失敗＝0（低估放行，第二道防線可用性優先）；bot/web 單專案錯誤回訊息不炸進程。
- .cmd 檔純 ASCII，改完必驗 `rg "[^\x00-\x7F]" scripts/<檔>` 零命中（硬規則 7）；重導向前置（踩雷 §24）。
- **排程任務全程維持停用**：安裝/更新後一律 `schtasks /change /tn <task> /disable`；驗收只用手動觸發；啟用時點由使用者決定。

export function globalBilledToday(cfgPath: string, nowIso: string): number {

    }
  } catch { return 0 }
