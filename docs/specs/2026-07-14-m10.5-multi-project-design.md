# M10.5 多專案常駐改造 Design Spec

日期：2026-07-14。狀態：使用者已核可設計五段（本檔為其正本）。
前情：M10.0（e66e665）讓 daemon 具備 perpetual 外環；但常駐層（排程任務、bot、web）全部硬編 voice-actress 單專案。使用者要求：**常駐基礎設施必須為所有專案服務**，接入體驗＝「丟 config 進 configs/ 就生效，移除即退場」。

## 1. 決策記錄（使用者選定）

| 軸 | 決定 |
|---|---|
| 接入體驗 | 丟 `configs/<專案>.json` 即納管；刪 config 即退場（≤15 分/≤一輪） |
| 錢的防線 | 全域日頂 `globalDailyHardUsd`（跨專案真金總帳），各專案日頂照舊 |
| bot 操作 | 無參數＝全部專案摘要；帶 `project` 參數＝單專案（前綴縮寫可） |
| 架構 | 方案 B：Windows 排程當 supervisor（boot＋15 分 refire＋lock 去重＝現成復活機制），不自寫 supervisor 進程 |
| 上線節奏 | 新排程任務安裝時**一律停用**；驗收用手動觸發；使用者點頭才 enable |

## 2. 現狀單專案假設（勘查結論，檔案:行號為 main@e66e665）

- daemon：**天生多實例安全**——daemon.lock/heartbeat/run.db/events 全在各自 dataDir（cli.ts:274、types.ts:82 dataDir 必填且 per-config 解析）。卡點只在 scripts/adng-daemon.cmd:19 硬編 voice-actress 與排程任務名唯一。
- bot（Discord slash commands，discord.js v14）：`main(cfgPath)` 一次綁死單一 `BotDeps`（bot/index.ts:47-66、handlers.ts:14-23）；12 指令（8 無參數＋4 帶參數）全閉包在單 cfg 上；bot.lock 在單專案 dataDir。
- web（server.mjs 540 行＋index.html 302 行）：單 `ctx` 閉包（server.mjs:498-517）、PORT=3900 硬編（:519）、面板指令轉呼叫 bot handleCommand（:404-415）——**bot 多專案化後 web 面板層近乎白撿**。
- 共用檔現況：`discordTokenFile` 預設值兩專案共用（types.ts:110，通知用）；`globalLearningsFile` 為設計好的跨專案共用縫（未啟用）；bot token 檔 `~/.adng/bot.env` 單一。

## 3. 元件規格

### 3.1 daemon 層（kernel +~5 行）

- **launcher** `scripts/adng-daemons.cmd`（純 ASCII，硬規則 7）：`for %%F in ("%ADNG_ROOT%\configs\*.json")` 每檔背景啟 `node dist\cli.js daemon --config <檔>`，log 重導向 `data\%%~nF\daemon-console.log`（**慣例：config 檔名＝data 目錄名**；不符慣例的 config 其 log 落錯目錄但功能不受影響——spec 明文接受）。重導向前置（踩雷 §24）；背景啟動方式由實作者在隱窗環境實測定案（踩雷 §20/§25：防黑窗與孤兒）。腳本本身不做迴圈監控——15 分 refire＋各 daemon 自己的 daemon.lock 完成去重與復活。
- **退場自查**（kernel）：runDaemon 迴圈每輪開頭 `if (!existsSync(cfgPath)) { events.append('daemon-config-gone'); break }`——cfgPath 經 opts 傳入（cli.ts daemon 子命令已有）。優雅退出走既有 releaseLock 路徑。
- **排程**：新任務 `adng-daemons`（BootTrigger＋PT15M repetition＋IgnoreNew，與現行三任務同形）指向新 cmd；舊 `adng-daemon` 任務刪除。新任務裝完即 `/change /disable`。

### 3.2 bot 多專案（src/bot/，不入 kernel 帳）

- **啟動**：新旗標 `--configs-dir <dir>`（與既有 `--config <path>` 互斥；`--config` 模式保留＝單專案向後相容）。載入 dir 下全部 `*.json`：逐一 `assemble()` 建 `Map<projectName, BotDeps>`，projectName＝config 檔名去 .json。**單一 config 載入失敗＝跳過＋console 警告＋照常服務其他專案（fail-open）**。
- **token**：`ADNG_BOT_TOKEN` env 優先；否則取第一個（檔名排序）有 `botTokenFile` 的 config。一進程一 Client。
- **指令 schema**：12 指令全部加可選 string option `project`。解析：精確匹配優先，否則唯一前綴匹配（`pro`→prompt-autoresearch；純字面前綴，`par` 這類非前綴縮寫不支援——YAGNI）；多義前綴→回覆候選清單。
  - **讀類**（/status /cost /backlog /log /problems /lessons）：無 project＝逐專案各一段摘要（只列該使用者在其 allowlist 的專案）；有 project＝單專案完整輸出（＝現行輸出）。
  - **動作類**（/pause /resume /task /goal /silence /ask）：**project 必填**，缺→拒絕並提示。對全部專案做動作不提供。
- **權限**：per-project `botAllowedUserIds` 照舊；路由層先解析 project 再查該專案 allowlist。guild 註冊：取第一個有 `botGuildId` 的 config（同一 guild 服務全部專案）。
- **lock**：改單一 `data/bot.lock`（repo 頂層 data/，非任一專案 dataDir）；`--config` 單專案模式維持原位置。
- **排程**：`adng-bot` 任務的 cmd 改為 `--configs-dir configs`；任務維持停用。

### 3.3 web 多專案（web/，不入 kernel 帳）

- 同 `--configs-dir` 模式建 `Map<projectName, ctx>`；`--config` 單專案模式保留。PORT 3900 不變（仍單進程單埠）。
- API 全部加 `?project=<name>`：`/api/status`、`/api/logs`（SSE）、`/api/panel/:name`、全部 POST。無 project 的 `/api/status` 回全專案摘要陣列（新形狀，供首頁卡片）。未知 project→404。
- CSRF token 改單一 `data/web-console.token`（頂層）；POST 驗證邏輯不變。
- index.html：首頁＝專案摘要卡清單（心跳狀態/今日成本/backlog 未完數/daemon 活否），點卡進單專案面板（現有 UI 照搬，所有 fetch 帶 project 參數）。
- `adng-web` 任務 cmd 改 `--configs-dir configs`；維持停用。

### 3.4 全域日頂（kernel 最大增量，估 +35~45 行）

- ConfigSchema 新欄：`globalDailyHardUsd: z.number().positive().optional()`——**選填；未設＝無全域防線（現狀）**。各 config 各自寫；慣例同值；生效以「當前專案自己 config 的值」為準（不做跨檔一致性檢查——YAGNI，spec 明文）。
- 新 kernel 小檔 `src/globalcost.ts`（估 ~40 行，2571→~2615 仍遠低於 2700）匯出 `globalBilledToday(cfgPath, offset, nowIso): number`：glob `dirname(cfgPath)/*.json` → 逐檔 parse 出 dataDir（容錯：壞檔跳過）→ 逐一唯讀開 `<dataDir>/run.db` 以 M9.9 `billedCostForLocalDay` 同語意加總真金（訂閱引擎不計）。**任何單檔失敗跳過該檔（fail-open：全域帳寧可低估，不因壞鄰居擋全部工作）**。
- 接線兩處：scheduler 成本閘（既有 per-project 日頂判斷旁，`billed_global >= globalDailyHardUsd` → cost-hard-stop，事件註明 global）；perpetual 外環 billedToday 閘同步（超全域頂→安靜讓路）。**每 cycle 快取一次**，不逐 attempt 重掃。
- 時區沿用各專案 `timezoneOffsetHours`（跨專案時區不一時各算各的日窗——接受的簡化，spec 明文）。

## 4. Fail-open 總則

- 壞 config：daemon launcher 啟了也會在 assemble 階段死掉（單專案自己的事）；bot/web 載入時跳過＋警告；globalBilledToday 跳過。任何情況不得拖垮其他專案。
- bot 單專案指令錯誤→回該專案錯誤訊息，不炸進程；SSE/面板同理。
- 全域頂查帳失敗→視為 0（低估放行），與 M9.9「引擎欄空算真金」的 fail-safe 方向相反——理由：全域頂是第二道防線，第一道（各專案日頂）仍在，可用性優先。

## 5. 測試

- bot：project 解析（精確/前綴/多義/未知）、無參數聚合只列有權限專案、動作類無 project 拒絕、單 config 壞檔跳過、`--config` 單專案回歸。
- web：project 參數路由、無參數摘要形狀、未知 project 404、token 驗證不變。
- kernel：daemon config-gone 優雅退場（注入假 existsSync 或 tmp 檔刪除）、globalBilledToday（暫存多專案 run.db 假資料：加總、壞檔跳過、訂閱不計）、成本閘全域頂觸發、perpetual 閘同步。
- 全部走既有 vitest serial；禁 sleep；既有 652 tests 斷言不動。

## 6. 驗收（真線，排程全程停用、手動觸發）

1. `adng-daemons.cmd` 手動跑一次：voice-actress＋prompt-autoresearch 兩 daemon 各自起、lock/heartbeat 各自寫；再跑一次＝no-op（lock 去重）。
2. 丟一個測試 config（指向暫存專案）→ 再跑 launcher → 第三個 daemon 出現；刪該 config → 該 daemon ≤一輪自退，其他兩個不受影響。
3. bot `--configs-dir`：/status 無參數列兩專案；/status par 單專案；/pause 無 project 被拒。
4. web 首頁兩張卡、點入面板正常。
5. 全域頂：暫調 `globalDailyHardUsd` 低於現有 billed 總和 → run-once 得 cost-hard-stop(global)；調回。
6. 驗收後排程任務維持停用，交使用者決定啟用時點。

## 7. 非目標（YAGNI）

- 不自寫 supervisor 進程（方案 A）、不做單 daemon 多專案（方案 C）。
- 不做 config 目錄即時監聽（15 分 refire 已滿足使用者核可的接入體驗）。
- 不做跨專案 config 值一致性檢查、不做多 guild bot、不做 web 真身分驗證（維持 localhost 模型）、不動 `discordTokenFile` 共用現狀。
- 不改 M10.0 外環邏輯本體（只接全域頂閘）。

## 8. 里程碑切分建議（給 writing-plans）

- M10.5.0：daemon launcher＋config-gone 退場＋排程任務改造（最小可用多專案常駐）。
- M10.5.1：全域日頂（kernel 錢防線先於 bot/web 上線）。
- M10.5.2：bot 多專案。
- M10.5.3：web 多專案＋真線驗收全項。
